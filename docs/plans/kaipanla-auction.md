# 开盘啦竞价工作台实施计划

> 状态：仅完成方案落盘，尚未实施。本文不包含任何 Token、UserID、DeviceID 或完整调用 URL。

## 1. 目标与已确认范围

在 TickFlow Stock Panel 中新增“竞价”一级父菜单。父菜单只负责展开，下面固定四个子菜单：

| 子菜单 | 路由 | 主要内容 |
| --- | --- | --- |
| 涨停委托 | `/auction/orders` | 三个竞价检查点的委买额和排名变化 |
| 竞价数据 | `/auction/data` | 可筛选、排序、虚拟滚动的竞价宽表 |
| 竞价洞察 | `/auction/insights` | 市场概览、个股榜单、题材聚合和负反馈 |
| 模型竞价 | `/auction/model` | AI 竞价报告生成、历史记录和导出 |

访问 `/auction` 时重定向到 `/auction/orders`。页面顶部不再重复放置四个页签。

本次明确不接入以下接口：

- `/104` 竞价砸盘
- `/112` 竞价净额大于 1000 万
- `/105` 竞价撮合大于 2000 万
- `/103` 尾盘竞价抢筹

“所有数据落库”指本功能实际发起的每次上游请求都保存原始响应和标准化结果，不代表调用逐股接口扫描全部 A 股。

## 2. 导航改造

- 为当前扁平导航项增加一层 `children`，只实现本需求需要的一层嵌套，不构建通用无限层级菜单。
- “竞价”父菜单使用 `Gavel` 图标和展开箭头，点击仅切换展开状态。
- 进入任一竞价子路由时自动展开父菜单并高亮当前子项。
- 增加键盘操作及 `aria-expanded`、`aria-controls`。
- 在现有菜单设置中，“竞价”作为一个整体参与排序和隐藏；四个子项顺序固定，不单独隐藏。
- 兼容已有 `nav_order` 和 `nav_hidden`，旧配置无需迁移。

## 3. 开盘啦凭据

在“设置 -> 数据源”增加“开盘啦竞价”辅助数据源，不改变 TickFlow 主行情数据源。

- 支持粘贴完整开盘啦调用 URL。
- 后端只解析并保存公共连接字段：`DeviceID`、`Token`、`UserID`、`PhoneOSNew`、`VerSion`、`apiv`。
- 不保存 URL 中的 `Type`、`PidType`、`Order`、`Index`、`st` 等接口业务参数。
- 导入后将凭据转换为 `/115` 的正式请求参数进行验证，不执行原始 URL 指向的 `Type=10` 请求。
- 凭据保存到本地 `data/user_data/secrets.json`，沿用现有脱敏和 `0600` 权限策略。
- 完整 URL 和凭据不得进入仓库、日志、错误响应、任务记录、测试夹具或报告输入。
- 上游主机采用代码内白名单，不允许用户提供任意目标地址。

## 4. 数据采集

### 自动采集

- 工作日 `09:15:05`、`09:20:05`、`09:25:05` 调用 `/115`。
- 使用 `Index` 分页，直到返回数量小于 `st` 或返回空列表。
- 采集 `/100` 最新龙虎榜股票数据，作为下一交易日的龙虎榜身份来源。
- 调度使用 `Asia/Shanghai` 时区；检查点采用较短的 misfire 宽限，错过后不补造实时快照。

### 按需采集

- `/31`：用户查看某只股票的竞价分时时请求，并将完整响应落库。
- `/113`：需要竞价量价历史或竞价量比时请求，并保存返回的全部日期、净额和竞价量。

### 手动历史回补

- `/30`：由用户选择日期范围后启动回补任务。
- 默认不自动回补历史。
- `/30` 只代表 `09:25` 定版；历史缺少的 `09:15`、`09:20` 必须显示“未采集”，不能填零。

### 可靠性

- 对超时、连接失败和可重试状态码执行有限次数退避重试。
- 每个检查点使用单实例锁，防止定时任务与手动采集重复并发。
- 重跑同一交易日和检查点时使用主键合并，不产生重复记录。
- 上游结构异常时保存原始响应并标记解析失败，不用部分错位字段覆盖成功数据。
- 应用未运行时错过的实时过程无法恢复，状态接口必须明确展示缺失检查点。

## 5. 存储设计

沿用项目的 Parquet 分区和 DuckDB 只读视图模式，按 `date=YYYY-MM-DD` 分区，写入采用临时文件加原子替换。

| 数据集 | 用途 |
| --- | --- |
| `auction_raw_responses` | 接口标识、采集时间、脱敏参数、原始 JSON、校验和、请求与解析状态 |
| `auction_snapshots` | `/115` 和 `/30` 的标准字段、检查点、股票及来源行序号 |
| `auction_stock_bid` | `/31` 的竞价时间、价格、方向、数量和开盘相关价格 |
| `auction_volume_history` | `/113` 的交易日、竞价净额和竞价量 |
| `auction_lhb_daily` | `/100` 的龙虎榜身份、净买额和基础指标 |
| `auction_daily_facts` | 三检查点合并、昨日身份、市值、题材、量比和质量状态 |
| `auction_report_runs` | AI 运行状态、输入快照、模型、结果、错误和完成时间 |

原始响应必须保留上游未知字段；标准化层严格校验 `/115`、`/30` 的数组列数和字段类型。

## 6. 流通市值口径

财务数据提供的是 `float_shares`，不是直接的流通市值。竞价事实表同时保存上游值和财务计算值：

- `kpl_float_market_cap`：开盘啦返回的实际流通市值。
- `finance_float_shares`：交易日当时已经公告的有效流通股本。
- `finance_float_market_cap`：竞价价格乘以有效流通股本。
- `float_market_cap`：页面最终采用值。
- `float_market_cap_source`：`kaipanla`、`financial_calculated` 或 `missing`。
- `float_market_cap_diff_pct`：两个来源同时存在时的差异比例。

取值优先级：

1. 开盘啦流通市值合法且大于零时优先使用。
2. 开盘啦值缺失时，使用竞价价格乘财务流通股本。
3. 实时竞价价格缺失时，使用昨收和竞价涨幅推算。
4. 历史股本只允许使用 `announce_date <= trade_date` 的最新记录，复用现有 `apply_historical_float_shares` 逻辑，防止未来数据穿越。
5. 两个来源差异超过质量阈值时标记“待核验”，不静默覆盖。

## 7. 连板与昨日身份

项目现有 enriched 数据已经保存：

- `consecutive_limit_ups`
- `consecutive_limit_downs`

现有连板梯队服务还会派生 `limit_up`、`broken`、`failed` 和 `boards`。竞价模块不再建立第二套连板算法。

- 昨日连板数、昨日涨停、炸板和断板身份关联前一交易日的现有数据。
- `/115` 返回的“6天4板”等文本保留为 `kpl_board_label`，用于展示和来源核验。
- 标准数值连板层级以项目的 `consecutive_limit_ups` 为准。
- `09:25` 不使用尚未收盘的当日行情重新判定炸板或断板。
- 为保证历史查询可复现，将关联结果物化进 `auction_daily_facts`，同时保存来源交易日。

## 9. 四个页面

### 涨停委托

- 三个交易日横向比较。
- 每日展示 `09:15`、`09:20`、`09:25` 委买额和排名变化。
- 支持交易日选择、检查点切换和 ST 过滤。
- 点击股票进入现有股票详情，并允许按需加载竞价分时。

### 竞价数据

- 使用虚拟化宽表、固定股票列、服务端筛选排序和分页。
- 展示竞价涨幅、委买额、净额、换手、成交额、主力资金、流通市值、题材、连板、龙虎榜和数据质量。
- 市值列展示最终采用值，并提供来源和差异状态。
- 展示真实返回数量和覆盖状态，不伪造全市场覆盖。

### 竞价洞察

- 市场概览结合 `/115` 与项目现有日 K。
- 题材强度按 `/115` 题材字段聚合。
- 个股榜单包括竞价涨幅、成交额、净额、换手、量比和昨日身份表现。
- 负反馈仅从 `/115` 中负竞价涨幅或负竞价净额记录派生。
- 不显示已排除接口对应的三个专用榜单。

### 模型竞价

- 复用现有 AI Provider 和 Markdown 渲染方式。
- 报告输入包含市场概览、榜单、题材、昨日身份、市值来源和质量状态。
- 支持手动生成、历史记录、复制和 Markdown 导出。
- 定时生成默认关闭，避免未经确认产生模型费用。
- 报告保持客观中立，不输出保证收益或明确买卖建议。
