# 两个聚宽策略分析与系统接入可行性

本文分析以下已归档源码：

- [`四合一打板.py`](./四合一打板.py)
- [`强者恒强.py`](./强者恒强.py)

结论先行：两份源码可以作为策略规则和参数的参考实现，但不能直接复制到本系统的自由策略运行器中执行。两者都依赖聚宽专有 API、全局运行状态和聚宽回调生命周期。可行的接入方式是“冻结原源码和参数 -> 按 TickFlow/自由策略契约重写 -> 逐项验证数据口径和成交结果 -> 再创建模拟盘”，而不是增加一个很薄的 `jqdata` 兼容层。

## 1. 结论摘要

| 策略 | 原源码直接运行 | 按本系统契约重写 | 主要阻塞 | 建议路线 |
| --- | --- | --- | --- | --- |
| 四合一打板 | 不可行 | 可行，但工作量高 | 四个模式、竞价/逐分钟盘中逻辑、估值/因子/概念、历史中证1000成分和 `jqmt` 订单桥 | 先拆分为共享候选快照 + 四个模式，再组合执行 |
| 强者恒强 | 不可行 | 可行，工作量中高 | 全市场逐股扫描、竞价和当前数据、秒级提示、资金环境动态参数、聚宽 `get_money_flow` 等 | 优先复用已有原生强动量快照结构，逐规则对齐源码 |

“可行”只表示存在明确的工程路径，不表示当前已经完成移植、回测一致或可以实盘下单。当前归档内容包含源码和成分股采集脚本；尚未创建系统策略、运行回测或创建模拟盘。

## 2. 四合一打板

### 2.1 策略结构

源码在初始化时注册 11 个日内任务，时间从 09:05 到 15:05，分别负责盘前静态预选、市场风控、竞价确认、开盘卖出、买入、午间情绪更新、午后卖出、日终审计和状态重置（`四合一打板.py:48-124`）。另外，`handle_data` 在交易时段按分钟执行概念退潮检查、委比/兼容买入、实时卖出和每 5 分钟波动率检查（`四合一打板.py:5574-5604`）。

四个模式共用股票过滤、概念和交易状态，但候选和买卖条件不同：

1. **一进二（yje）**：从上一交易日涨停股开始，计算板块质量、概念、成交和竞价强度，使用委比和盘口条件确认买入。
2. **弱转强（rzq）**：从炸板股和近期形态中筛选，要求历史涨停次数、均线、涨幅、成交额、市值和竞价区间满足条件。
3. **趋势股（qs）**：先过滤中证 1000 成分，再计算均线、动量、ATR、概念和组合评分；有最长持有日和 ATR 止损。
4. **首板（sb）**：盘前做市值、PE、60 日成交额和均线斜率筛选，盘中依据触板、委比和封板质量买入。

代码把四个模式的候选和状态保存到 `g.yje_*`、`g.rzq_*`、`g.qs_*`、`g.sb_*` 等字段，并在代码更新/进程重启时迁移部分状态（`四合一打板.py:585-637`、`四合一打板.py:5504-5569`）。这属于跨日状态策略，不能只把选股函数接入系统而忽略状态快照。

### 2.2 数据和外部依赖

源码使用 `jqdata`、`jqfactor`、`jqlib.technical_analysis`、`talib` 和可选的 `jqmt`（文件头部导入）。实际调用包括：

- 日线、分钟线、当前行情和历史行情：`get_price`、`attribute_history`、`get_current_data`、`get_current_tick`；
- 标的目录和名称/交易状态：`get_all_securities`、`get_security_info`；
- 估值：`get_valuation`；
- 因子：`get_factor_values`，默认因子为 `VOL5`；
- 概念/行业信息及概念统计：源码中的概念和行业映射调用；
- 技术指标：滚动均线、RSI/MACD 类计算、ATR 和 `talib.ATR`；
- 竞价和盘中微观结构：当日开盘、涨跌停价、盘口/委比和逐分钟价格；
- 订单桥：`ENABLE_LIVE_TRADING=True` 时把聚宽订单函数包到 `jqmt.push_order*`，这不是本系统自由策略的订单接口（`四合一打板.py:126-138`）。

这些调用不能通过当前自由策略引擎直接满足。该引擎加载源码时只注入 `run_daily`、`run_weekly`、`run_monthly`、`unschedule_all` 和受控 `context`，策略需要使用 `context.set_universe`、`context.history*`、`context.order_*` 等接口（`backend/app/free_strategy/engine.py:970-1020`、`backend/app/free_strategy/engine.py:660-890`）。源码中的 `from jqdata import *`、全局 `g`、`OrderCost`、`FixedSlippage` 和 `handle_data` 均没有对应的直接兼容契约。

### 2.3 成分股使用

趋势股模式明确请求 `get_index_stocks('000852.XSHG', date_str)`，即按目标日期取得中证 1000 成分并与基础股票池取交集（`四合一打板.py:3491-3503`）。这是严格的历史成分依赖：不能用今天的中证 1000 成分回填历史，也不能把用户导出的某一天 Excel 当成全历史成分。

本系统已有 PIT 指数成分历史的存储和校验工具，但自由策略运行时没有一个可直接替代 `get_index_stocks(index, date)` 的公开 `context` 方法；同时，具体指数的覆盖和完整性必须在运行前由 readiness 检查确认。接入时应：

1. 新增一个只读的指数成分快照 loader，输入 `index_symbol=000852.SH` 和 `snapshot_date`，输出规范化的 `.SH/.SZ/.BJ` 代码。
2. 只从 canonical PIT index membership 表读取，并校验目标日期快照完整、无冲突、数量在指数规则范围内。
3. 缺历史快照、成员数异常或同日来源冲突时，整个趋势股候选阶段失败关闭，不回退到当前成分或全市场列表。
4. 将成分快照日期、来源和成员数量写入回测/模拟 metadata，便于与聚宽结果逐日核对。

源码其他模式使用的是全市场基础池和概念/行业过滤，不应把“中证 1000 成分股”误扩展到四个模式。成分池身份必须保留在趋势股模式内部。

### 2.4 接入拆分

建议拆成以下层次：

1. **候选快照层**：盘前按 D-1 及以前数据计算四个模式的静态候选；09:25 后单独加载竞价快照完成确认。候选快照必须包含 `as_of`、数据覆盖、过滤原因和来源哈希。
2. **模式执行层**：将 yje、rzq、qs、sb 分成四个纯规则模块，共享标准化股票、涨跌停、估值、概念和订单接口。
3. **组合层**：复现优先级、总持仓上限、首板 30% 资金上限、趋势股名额限制和卖出先于买入的顺序。
4. **盘中事件层**：用 `on_bar(context, bars)` 消化逐分钟检查；`handle_data` 不能被假定为会自动执行。需要实时报价时使用 quote/实时行情路径，缺失或过期则等待，不使用当日历史 K 线冒充实时成交。
5. **状态层**：将 `g` 中的可持久化状态迁移到 `context.state`，将进程内缓存留在运行时缓存中；重启要通过检查点恢复，而不是重新初始化为空状态。

### 2.5 主要风险

- **竞价时点**：09:25:45、09:27、09:28 的顺序会直接改变候选和成交，历史分钟数据不能证明秒级竞价可成交。
- **涨停成交**：源码的触板、封板和委比买入不等于实际排队成交。回测需要明确“触板模拟成交”与“真实委托成交”的边界。
- **数据规模**：盘前对全市场做多模式批量筛选，必须使用 Polars/批量 loader，不能逐股 N+1 请求。
- **QMT 桥接**：`jqmt` 推送不能从策略源码直接调用。系统实盘委托必须经过已有 QMT 服务、账户校验、资金预检和实盘开关；第一阶段只允许纸盘。

## 3. 强者恒强

### 3.1 策略结构

策略以“强势股识别 + 竞价确认 + 早盘分批买入 + 盘中破板/止盈止损”为主。默认参数包括：最大持仓按资产分层为 2/3/4/5/8 只，单日买入上限同步分层；止损 -4%、止盈 19%、最长持有 3 日、从日内高点回撤 1.5% 触发卖出（`强者恒强.py:9-87`）。

盘前从当日可交易股票中排除北交所、科创板、ST/风险股，再识别涨停或强势股，依次应用连续涨幅、14:30 后涨幅、振幅、换手、近三日跌停、缩量上涨等过滤；候选为空时使用宽松和超宽松识别（`强者恒强.py:1001-1079`）。

竞价阶段按开盘涨幅、昨日成交量/涨停状态和风险阈值过滤（`强者恒强.py:1083-1152`）。09:30 后先处理未涨停持仓和卖出规则，再在 09:30:16、09:31、09:32、09:37、10:29 等时间点分批买入；10:00 至收盘前按 2 分钟间隔检查破板回撤。策略还在 09:30:16 和 09:33:16 输出手动跟单提示。

### 3.2 数据和外部依赖

除日线和分钟行情外，源码依赖 `get_money_flow`、`get_industry`、`get_concept`、`get_all_securities`、`get_security_info` 和 `get_current_data`。市场环境根据沪深 300 前一日涨跌和抽样涨停数量调整开盘涨幅、换手和止盈止损参数（`强者恒强.py:951-999`）。

本系统可提供标准化日线/分钟 K、交易日历、实时快照、历史名称和统一撮合，但没有把聚宽的行业概念、资金流和 `get_current_data` 对象原样暴露给自由策略。迁移时应把每一项改成显式 loader 或快照字段，并记录来源及截止时点。资金流若没有同口径历史数据，应跳过该过滤并标记为不可验证，不能静默用成交额替代。

### 3.3 接入拆分

1. **强势候选快照**：复用/扩展系统已有 `strong_momentum_snapshot` 结构，将 D-1 的涨幅、换手、成交量增长、涨停/跌停、振幅、缩量上涨和历史名称过滤一次性批量生成。
2. **实时竞价快照**：在 09:25/09:30 读取实时开盘、涨跌停和成交字段；快照缺失或超过新鲜度阈值时返回 `waiting_market`，不进行买入。
3. **分钟执行**：将源代码的秒级回调降级为系统可证明的分钟边界，或扩展 quote 事件后再做秒级纸盘验证。仅有 1 分钟历史 K 时，不能声称复现 09:30:16/09:33:16。
4. **信号和提示**：自动买卖使用统一订单接口；手动跟单改为 `context.emit_signal`，由系统通知/审计消费，不能直接打印成“已成交”。
5. **状态恢复**：持有日、当日买入集合、已涨停集合、破板卖出集合和候选池都纳入 checkpoint；回测和模拟使用同一源码哈希、参数和数据能力。

系统已有项目原生的 `backend/app/free_strategy/strong_momentum.py` 和 `strong_momentum_snapshot.py`。它们不是这份聚宽源码的自动证明，但提供了正确的工程落点：候选由 PIT 日快照生成，分钟阶段只处理候选和持仓，订单、T+1、涨跌停和费用由公共引擎负责。应在其上逐项对照源策略，而不是再复制一套 `jqdata` 兼容运行时。

## 4. 两策略与本系统的契约差异

| 领域 | 聚宽源码假设 | 本系统接入要求 |
| --- | --- | --- |
| 源码入口 | `initialize`、`handle_data`、`run_daily` 和 `g` | `initialize(context)`、`before_trading_start`、`on_bar/on_quote`、`context.state` 和 `context.schedule` |
| 标的池 | `get_all_securities`、`get_index_stocks` 动态查询 | 策略声明/快照 loader 提供规范化代码；影响结果的维度进入 metadata |
| 历史数据 | 聚宽 DataFrame API，可能按调用时点返回 | TickFlow 仓库 + 明确 cutoff；不得未来函数，不得用当前快照替代历史 PIT |
| 当前行情 | `get_current_data`、`get_current_tick`、竞价和盘口 | 实时行情或受控事件快照；缺失/过期时等待 |
| 费用滑点 | `OrderCost`、`FixedSlippage`/`PriceRelatedSlippage` | `FreeStrategyConfig` 的 commission、印花税、过户费、滑点、最小佣金和成交策略，需逐项校准 |
| 订单 | `order_target*`，可选 `jqmt` 推送 | `context.order_target*`/`buy`/`sell`，真实 QMT 由独立服务控制 |
| 调度 | 支持聚宽特殊时间和秒级字符串 | 定时表达式为分钟精度；`before_open`/`after_close` 需映射，秒级只能在 quote 路径验证 |
| 结果 | 聚宽日志、订单和持仓状态 | fills、signals、logs、源码哈希、readiness manifest 和逐日/逐笔审计 |

自由策略引擎确实支持定时模式、分钟回放、T+1、卖出优先和 checkpoint，但它只会执行已注册的系统回调；没有 `on_bar` 的源码会被识别为 scheduled，源码中的 `handle_data` 不会自动接入。定时表达式只接受 `HH:MM`、`every_bar` 或开收盘分钟偏移（`backend/app/free_strategy/schedule.py:16-33`）。

## 5. 成分股和数据接入方案

### 5.1 中证 1000

只属于四合一的趋势股模式。接入前必须有：

- `000852.SH` 的历史每日成分快照或事件表；
- 代码、交易所和生效日期标准化；
- 目标日期成员数量、重复键和来源冲突校验；
- 回测/模拟一致的 snapshot loader 和 readiness 报告。

没有完整历史覆盖时，趋势股模式应返回不可用并保留其他模式的明确状态，不能把初始全市场列表当成等价回退。若业务要求四模式必须整体一致，则整个策略任务应失败关闭，而不是只悄悄放宽趋势股池。

### 5.2 概念、行业和资金流

四合一使用概念统计和概念过滤，强者恒强展示并参与行业/概念判断。当前系统的 PIT 行业能力必须指定标准和层级；当前概念/板块扩展数据属于辅助来源，不能未经时间点验证就作为历史回测事实。资金流同理，必须声明 provider、字段口径、日期可见性和缺失行为。

### 5.3 竞价和实时行情

两策略都在开盘前后使用当日数据。历史回测可以使用按时间切分的分钟/竞价快照，但不应从收盘日线反推 09:25 盘口。模拟盘必须使用实时行情；当日覆盖不足、报价陈旧、涨跌停字段缺失或标的未订阅时，状态应为等待，不得以历史 K 线补成交。

## 6. 推荐实施顺序

### 阶段 A：冻结和可审查化

1. 为两份源码建立稳定策略 ID、源码哈希、参数快照和来源链接。
2. 把聚宽参数、调度表、过滤器、订单规则和状态字段整理成结构化清单。
3. 明确验收目标：是“规则迁移”、还是“逐笔交易与聚宽对齐”。两者不能混称。

### 阶段 B：先接入强者恒强

1. 复用 `strong_momentum_snapshot`，完成 D-1 候选快照和历史名称/PIT 过滤。
2. 将聚宽回调改成 `before_trading_start` + 分钟 `on_bar`，把秒级手动提示改成系统 signal。
3. 对 1 个完整历史区间做逐日候选、订单和费用核对，再进入模拟盘。

### 阶段 C：拆分四合一

1. 先只实现 yje、rzq、sb 三个依赖股票/竞价的模块，建立独立事件类型和候选审计。
2. 解决 `000852.SH` PIT 成分后再接 qs；禁止先用全市场回退来“跑通”。
3. 最后实现组合优先级、资金上限、午间动态调整和跨日状态恢复。

### 阶段 D：模拟盘和真实交易边界

1. 使用已验证回测的源码哈希、参数、起始日和检查点创建模拟账户。
2. 先验证实时行情等待、恢复、卖出优先、T+1、涨跌停不可成交和通知信号。
3. 实盘委托若有需求，只通过独立 QMT 服务和账户开关进行小额联调；不能通过策略里的 `jqmt` 导入绕过系统风控。

## 7. 验收标准

接入完成前至少要有以下证据：

- `git diff --check`、源码 AST/导入检查和定向策略测试通过；
- readiness 报告列出日线、分钟、实时、估值、概念/行业、资金流和指数成分的实际覆盖；
- 回测逐笔对比时间、代码、方向、数量、价格、金额、费用和状态，首个差异可定位；
- 关键边界覆盖无数据、竞价缺失、停牌、涨停/跌停、T+1、现金不足、代码更新和进程重启；
- 模拟盘证明使用实时行情，缺失时等待，并通过检查点恢复持仓、策略状态和源码指纹；
- 未经逐笔对账，不得在 UI 或文档中写“完全复现聚宽”。

### 最终判断

这两个策略值得接入，但应作为两个独立的“外部规则迁移”项目。强者恒强适合先基于系统已有原生强动量快照做规则对齐；四合一打板应先拆模块并完成中证 1000 PIT 成分能力，再考虑组合级模拟。直接把聚宽文件放进 `data/free_strategies` 只能完成源码归档，不能完成系统接入。
