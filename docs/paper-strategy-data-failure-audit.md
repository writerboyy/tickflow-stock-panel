# 模拟盘策略数据缺失与错误清仓风险审计

审计日期：2026-08-06

## 1. 审计目标与范围

本次审计由“七星策略因 ETF 净值缓存过期，先卖出旧持仓后无法买入新标的”事件触发，检查当前模拟盘策略是否存在以下同类风险：

1. 外部或本地上游数据过期，但策略仍将旧数据当作当日数据使用。
2. 数据缺失被当作“标的不合格”或“有效空候选”。
3. 在新目标尚未通过完整校验前先卖出旧持仓。
4. 内置策略已修复，但运行中的模拟盘仍使用旧源码快照。

审计覆盖当前运行的五类策略：

- 七星策略 r3（模拟盘名称：ETF 动量轮动敏感）
- ETF 动量轮动 r9（模拟盘名称：ETF 动量轮动钝化，本文简称五福 1.0）
- 五福 2.0 r2（模拟盘名称：ETF 动量轮动钝化 2.0）
- 绩优小市值 r11、r12
- 涨停基因小市值 r2

运行时账户目录属于本地数据，不纳入 Git。本文记录策略族、修订版本和行为结论，不记录账户 ID、通知地址或其他用户配置。

## 2. 结论摘要

| 策略 | 是否受 ETF 净值缓存影响 | 是否可能因数据异常错误卖仓 | 当前判断 |
| --- | --- | --- | --- |
| 七星策略 r3 | 是 | 是，且已发生 | 严重：旧持仓按原始排名先卖，净值缺失后无新目标，形成空仓 |
| 五福 1.0 r9 | 是 | 是 | 高风险：使用过期净值计算溢价，可能错误换仓或错误切换防御标的 |
| 五福 2.0 r2 | 是 | 不是同一空仓路径，但有其他风险 | 中风险：溢价值过期，且当前过筛未真正执行溢价条件 |
| 绩优小市值 r11、r12 | 否 | 是 | 高风险：财务、估值或分红筛选数据为空时，月度调仓可把空结果当成有效目标并卖仓 |
| 涨停基因小市值 r2 | 否 | 是 | 高风险：标的、历史行情或行业数据异常导致空选股时，周调仓可卖出非目标持仓 |

只有七星策略已经确认出现错误空仓。其他策略当前仍有持仓，但存在需要修复的同类保护缺口。

## 3. 已确认事件：七星策略 r3

### 3.1 实际执行链

2026-08-05：

1. 原持仓为 `513690.SH`。
2. 当日原始动量排名第一变为 `513050.SH`。
3. 13:09，策略在溢价校验之前卖出 `513690.SH`。
4. 13:10，所有候选因缺少上一交易日精确净值而未通过买入资格。
5. 账户变为空仓，2026-08-06 因仍无合格目标继续空仓。

对应代码：

- [`_sell_targets`](../backend/app/free_strategy/seven_stars.py#L445-L460) 按未经过净值过滤的 `raw_targets` 先卖旧持仓。
- [`_passes_premium_filter`](../backend/app/free_strategy/seven_stars.py#L369-L387) 要求净值日期与上一交易日精确一致。
- [`_eligible_targets`](../backend/app/free_strategy/seven_stars.py#L463-L474) 只接受净值检查结果为 `True` 的候选。
- [`_buy_targets`](../backend/app/free_strategy/seven_stars.py#L477-L486) 的保留持仓保护发生在卖出之后，旧持仓已经卖掉时无法生效。

### 3.2 不是实际高溢价

上游最新数据表明：

| 判断日期 | 标的 | 上一交易日收盘价 | 对应单位净值 | 溢价率 | 20% 阈值结果 |
| --- | --- | ---: | ---: | ---: | --- |
| 2026-08-05 | `513050.SH` | 1.1780 | 1.1888 | -0.91% | 通过 |
| 2026-08-06 | `513050.SH` | 1.1890 | 1.1972 | -0.68% | 通过 |

因此空仓不是策略的真实溢价过滤结果，而是本地净值未更新造成的错误拒绝。

## 4. 共享根因：ETF 净值缓存不会增量更新

共享加载器 [`load_fund_nav_history`](../backend/app/free_strategy/fund_nav.py#L79-L132) 当前只在缓存文件完全不存在时拉取远端数据：

```python
cached = _read_cached_nav(path)
if cached:
    values[symbol] = cached
else:
    missing.append(symbol)
```

只要缓存非空，即使最后日期已经落后多个交易日，也不会进入远端刷新队列。

本次抽查结果：

| 标的 | 本地旧格式缓存物理日期 | 运行时规范化后的最晚日期 | 上游可用日期 |
| --- | --- | --- | --- |
| `513050.SH` | 2026-07-23 | 2026-07-24 | 2026-08-05 |
| `159980.SZ` | 2026-07-26 | 2026-07-27 | 2026-08-06 |
| `159920.SZ` | 2026-07-26 | 2026-07-27 | 2026-08-06 |
| `517520.SH` | 2026-07-26 | 2026-07-27 | 2026-08-06 |

旧格式缓存会在读取时进行中国时区日期修正，因此“物理日期”和“运行时日期”相差一天；无论按哪种口径，都明显落后于策略所需日期。

另一个共享问题是 `extra_history` 返回“截止日期之前最后一条数据”，没有同时返回期望日期与实际数据日期的匹配状态。未自行校验日期的策略会静默使用旧净值。

## 5. 其他 ETF 策略

### 5.1 五福 1.0 r9：会使用旧净值参与真实过滤

结论：受影响，但当前症状通常不是直接空仓，而是错误过滤、错误换仓或错误切换防御标的。

关键行为：

- [`_metric_for`](../backend/app/free_strategy/five_fortunes.py#L804-L854) 读取最后一条净值，但没有校验净值日期是否等于 `nav_date`。
- `passed_premium` 要求溢价可计算且不超过阈值。
- [`_prepare_and_sell`](../backend/app/free_strategy/five_fortunes.py#L581-L647) 先生成过滤后的目标，再卖出不在目标中的持仓。
- 当全部候选被过滤时，通常会切换 `511880.SH` 防御标的；防御标的行情也不可用时，目标可为空并卖出旧持仓。

2026-08-06 的运行状态中，`159980.SZ` 的溢价被计算为约 2.15%。该数值使用了 7 月下旬净值；使用 2026-08-05 最新净值重新计算约为 0.24%。当前两者都未超过阈值，但靠近阈值的标的可能因此产生相反结论。

风险等级：高。原因是错误数据已经进入实际选股和换仓决策，只是本次尚未形成空仓。

### 5.2 五福 2.0 r2：不会因净值缺失走相同空仓路径，但溢价保护无效

结论：共享净值缓存同样过期，但当前代码对缺失净值采用放行，并且过筛函数没有检查 `passed_premium`。

关键行为：

- [`_metric_for`](../backend/app/free_strategy/five_fortunes_v2.py#L972-L1029) 将净值缺失视为通过。
- [`_passes_filters`](../backend/app/free_strategy/five_fortunes_v2.py#L1032-L1045) 没有使用 `passed_premium`。
- [`_prepare_and_sell`](../backend/app/free_strategy/five_fortunes_v2.py#L707-L758) 在卖出前已经产生目标，因此不会复现七星的“原始排名先卖”路径。
- 新目标可能等待盘中趋势确认，但 14:55 有强制买入流程；这是策略设计，不是净值缺失造成的空仓。

2026-08-06 的运行状态中，`517520.SH` 溢价记录约为 9.37%，使用的是 7 月下旬净值；使用 2026-08-05 最新净值重新计算约为 0.19%。该错误目前主要影响日志、报告和风险解释，但也说明配置中的溢价保护没有按预期生效。

风险等级：中。不会因净值缺失直接空仓，但可能买入本应被高溢价过滤的标的。

## 6. 股票策略的同类风险

股票策略不调用 `unit_net_value`，因此不受 ETF 净值缓存问题影响。但它们同样缺少“数据不可用”和“有效空候选”的结构化区分。

### 6.1 绩优小市值 r11、r12

候选依赖：

- 分红排序
- 财务快照
- 估值市值
- 日线行情与盘中可交易快照

[`_financially_qualified`](../backend/app/free_strategy/performance_small_cap.py#L189-L211) 在加载器不可用时返回空列表；[`_valuation_market_caps`](../backend/app/free_strategy/performance_small_cap.py#L165-L176) 在异常时返回空字典。之后 [`_monthly_adjustment`](../backend/app/free_strategy/performance_small_cap.py#L636-L652) 会把空选股结果当作有效目标，卖出所有不在目标中的持仓。

风险等级：高，但只在月度调仓或首次调仓窗口暴露。当前运行账户未出现该问题。

### 6.2 涨停基因小市值 r2

候选依赖标的维表、日线行情、历史涨停识别和行业数据。运行中的 r2 会缓存空选股结果；周调仓卖出逻辑会把不在空目标中的旧持仓卖出。

内置模板已经增加部分保护，例如行业快照缺失时明确失败、空结果不缓存，但运行中的模拟盘保存的是 r2 源码快照，不会自动继承模板修复。即使使用新模板，仍需要在卖出入口增加“选股数据完整性”保护。

风险等级：高，但当前运行账户未出现该问题。

## 7. 必须实施的防线

### P0：修复共享 ETF 净值加载器

1. 读取缓存后计算规范化的最大日期。
2. 最大日期早于所需截止日期时执行增量拉取，而不是仅在文件不存在时拉取。
3. 合并缓存与远端数据，按 `symbol + date` 去重并排序。
4. 使用临时文件加原子替换写回，远端失败时保留原缓存。
5. 返回每个标的的 `required_date`、`actual_date`、`freshness_status`，不能只返回“文件是否存在”。
6. 实时策略按上一交易日校验，不用自然日推断交易日。

### P0：交易入口禁止把数据异常当成空目标

策略选择结果应使用结构化状态：

```text
status = ok | unavailable
targets = [...] | []
as_of = 数据实际截止日期
missing_inputs = [...]
```

- `status=unavailable`：保留已有持仓，不发送策略换仓卖单，并发出告警。
- `status=ok, targets=[]`：只有策略业务规则明确允许空仓时，才可执行清仓。
- 止损、回撤保护等独立风险卖出不受此保护阻断。

### P0：先完成目标资格校验，再卖旧持仓

七星策略必须改为：

```text
排名 -> 行情/净值/溢价完整性检查 -> 得到合格目标 -> 生成原子调仓计划 -> 卖旧买新
```

没有合格目标且原因是数据不可用时，应记录 `data_unavailable_hold`，而不是 `no_eligible_target`。

### P1：逐策略修正

- 七星：移除基于 `raw_targets` 的提前卖出；缺净值时保留持仓。
- 五福 1.0：要求净值日期精确匹配；数据异常时不切防御标的、不换仓。
- 五福 2.0：明确决定是否启用溢价过滤；启用时必须校验日期并在 `_passes_filters` 中执行，禁用时不要展示“已启用”的误导状态。
- 绩优小市值：财务、分红、估值数据建立最低完整率；未达标时暂停月度调仓。
- 涨停基因小市值：选股输入不完整时暂停周调仓；不得缓存由数据异常产生的空结果。

### P1：模拟盘源码版本迁移

模拟盘创建时会保存策略源码快照。修复内置策略模板后，已有账户不会自动更新，必须：

1. 创建新的策略修订版本。
2. 校验新修订与回测结果的源码哈希一致。
3. 通过检查点迁移已有模拟盘状态、持仓和策略 state。
4. 迁移后核对账户的 `source_revision` 与 `source_hash`。

## 8. 必须增加的测试

1. 非空但过期的净值缓存会触发增量刷新。
2. 增量刷新合并后不丢历史、不产生重复日期。
3. 远端失败时保留旧文件，并返回 `unavailable`，不伪装成最新。
4. 七星排名切换且净值缺失时不发送卖单。
5. 七星净值正常且溢价合格时完成换仓。
6. 七星真实高溢价时跳过该候选并继续寻找下一候选。
7. 五福 1.0 不使用日期不匹配的旧净值。
8. 五福 2.0 的溢价开关、过筛行为和页面状态一致。
9. 绩优小市值财务或估值数据不可用时不执行月度卖仓。
10. 涨停基因小市值选股数据不可用时不执行周度卖仓。
11. “完整数据下确实无候选”和“数据不可用”产生不同决策码。
12. 策略新修订迁移后，运行账户实际使用新的源码哈希。

## 9. 修复完成标准

以下条件全部满足后，才能认为该类问题已关闭：

- ETF 净值缓存能够增量更新到上一交易日。
- 所有策略决策都能区分有效空候选和数据不可用。
- 任何候选数据故障都不会触发普通策略换仓卖单。
- 风控卖出仍能独立执行。
- 页面和通知明确显示“数据异常，保留持仓”，不显示“保持空仓”或“无合格标的”。
- 所有现有模拟盘完成策略修订迁移并核对源码哈希。
- 上述测试全部通过，并在模拟盘页面完成一次有持仓、一次换仓和一次数据故障演练。
